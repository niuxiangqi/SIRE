# DECISIONS — SIRE v0

| # | Decision | Reason | Evidence |
|---|---|---|---|
| 1 | Environment `sire` is a conda clone of the pre-existing `qwen38_engines` env (torch 2.13, transformers 5.17), plus datasets/pandas/matplotlib/accelerate/modelscope. | Avoid a multi-GB reinstall; the clone has a working CUDA 13 torch and Qwen2 support. | `runs/<id>/env/pip-freeze.txt`, `env.json` |
| 2 | Models are read from the fixed KEPT paths; B and R are never modified. All runs use R's config/tokenizer/chat template. | Contract; audit records the actual differences (rope_theta, sliding_window). | `runs/<id>/audit/model_audit.json` |
| 3 | Data downloaded from ModelScope mirrors of `AI-MO/NuminaMath-CoT` and `HuggingFaceH4/no_robots` because direct Hugging Face DNS/endpoints were unreachable from this host. | Numeric answer filtering and file hashes make the exact bytes auditable. | `splits.json` `dataset_files_sha256` |
| 4 | Ground truth is the first parseable numeric expression scanning boxed answers from the end; non-numeric/proof/open/multiple-choice-letter answers are excluded. | A single verifiable scalar per item; checking is exact rational comparison where possible. | `load_stats` in `splits.json` |
| 5 | Near-duplicate control: exact normalised dedup then 64-bit SimHash with 4x16-bit LSH bands, verified by Hamming<=3 or character-4-gram Jaccard>=0.8. One representative per cluster; splits are cluster-disjoint. | Exhaustive pairwise comparison over ~90k candidates is too slow; 4x16 bands guarantee recall for Hamming<=3. | `dedup` block in `splits.json` |
| 6 | Candidate pool capped deterministically at 50,000 cn_k12 items (hash order) before dedup. | Full 89k-item SimHash/LSH run was unnecessary for 44 items and slowed preparation; the cap is a uniform hash sample, not correctness-based. | `load_stats.pool_cap` |
| 7 | Features store D/G/U as FP16 on disk, but all scoring and RMS statistics are FP32/FP64. B/R are read from pristine safetensors. | Disk/RAM economy without changing the comparison computation; audit records the storage dtype. | `features/meta.json` |
| 8 | Gradient statistic G/U uses FP32 R parameters with TF32 matmul enabled, microbatch 1, gradient checkpointing, per-sample forward/backward and immediate FP32 CPU accumulation. | GOAL requires FP32 statistics and no per-sample gradient retention. | `features/meta.json`, `budget.json` |
| 9 | Generation uses a custom batched decode loop with one CUDA generator per item seeded from (global seed, item id), rather than `model.generate`. | Per-item seeds must be independent of batch/resume order. | `eval.item_seed`, per-sample `seed` field |
| 10 | Stop ids are R eos (151643) and `<|im_end|>` (151645); all other decoding settings frozen in config. | A completed chat turn ends at im_end; recording it in config keeps one protocol for every method. | `configs/v0.yaml`, `splits.json` `generation_config` |
| 11 | `rho=1` reconstructs via an explicit all-true `where(mask, R, B)` and is checked bitwise against pristine R. | Contract; avoids subtract-add drift. | `correctness/results.json` |
| 12 | Sizes may be reduced once (search/selection/test = 4/4/8) and dense middle rho points dropped (0.02 then 0.50) only if the pilot projection exceeds 88% of remaining budget, before formal evaluation. | Contract allows one reduction; the decision is recorded in `pilot.json` and `frozen_config.yaml`. | `pilot.json.decision` |
| 13 | Test is opened only after `freeze.json`; `search.run_search` receives a manifest view with only search/selection splits. | Prevent test leakage into search/selection. | `cli.stage_search`, `verify` C5 |
| 14 | Random retention uses a SHA-256-derived torch RNG seed per (global seed, rho, tensor). | Reproducible and independent of evaluation order. | `masking.random_indices` |
| 15 | Acceptance verify recomputes quotas, item counts, hashes, curve aggregates and regenerates root artifacts; it fails on byte mismatch. | Contract C8 / "must not read a human-written passed field". | `verify.json` |
| 16 | Formal run stopped twice because physical GPU 4 disappeared (`0000:1A:00.0: Unknown Error`, `lspci ... rev ff`). No card switch during those attempts, no host reboot, no other-user process killed. | Contract section 14: GPU 4 unavailable is a block condition. | `BLOCK_REPORT.md`, `evidence/gpu4_failure_20261020/`, `evidence/gpu4_failure_20261021/` |
| 17 | The 5 s GPU monitor now selects the expected UUID explicitly; the first version logged the first `nvidia-smi` row (GPU 0). | Monitoring must corroborate isolation on the target GPU, not just show that some GPU exists. | `util.GpuMonitor` |
| 18 | On 2026-10-27 the user explicitly authorized switching the formal run to **physical GPU 2** (UUID `GPU-8a98ac52-...`) after GPU 4 failed twice at the PCIe level. The run continues from `v0-20261021-formal`; model/data/precision/generation protocol is unchanged. The switch itself could not execute until the host driver was reloaded; after reboot the run completed on GPU 2. | Contract says paths/device must never change silently; this is an explicit user-authorized hardware substitution, not a silent switch. | `runs/v0-20261021-formal/device_migration.json`, `evidence/gpu2_switch_20261027/`, `verify` C1 |
| 19 | Search counts "new candidates" by the full anchor mask signature, excluding signatures equal to the A or Neg(U) baselines. This was fixed mid-run after discovering that `A*U` and `|A|*U` produce identical masks and that `|A|` equals baseline A. | Contract: mask-hash-equivalent candidates must not count as new formulas. | `search.distinct_new_masks`, C4 detail `distinct_mask_signatures: 8` |
| 20 | The test curve was reduced from 7 to 5 keep-rates by dropping `rho=0.02` and `rho=0.50`, before their results were seen, because the measured test throughput projected over the remaining budget. | Contract permits dropping dense-middle points in that fixed order and recording the reduction. | `curve_reduction.json`, `RESULTS.md` |
| 21 | Final scientific outcome is **negative**: full R 3/8 (6/8 truncated), searched `A*U` best 2/8 at rho=0.30, random/A/Neg(U) 0/8 at every tested rho, `rho*=n/a`. | Report measured values only; 8 items and a 2048-token cap give wide uncertainty. | `RESULTS.md`, `curve.csv`, `reports/REPORT_EN.md`, `verify.json` |
| 22 | No sparse model checkpoints are persisted. A candidate is reconstructed from pristine B/R + formula + feature cache; only AST, mask hashes, per-sample outputs are saved. The 54 GB feature-gradient accumulator is disabled by default and recomputed on resume. | Writing/reading the accumulator costs minutes and tens of GB, while 8 calibration gradients cost only a few seconds of CUDA compute; per-candidate weights are cheap to regenerate. GOAL section 12 now states this policy. | `GOAL.md`, `configs/v0.yaml` (`features.save_accumulator: false`), `features.py` |
| 23 | Post-hoc external tests use GSM8K test (8 items, pass@4, 4 samples/item) and 4 medical MMLU subjects (16 items, pass@1), reusing the frozen formula. They are outside C1–C8 and keep a separate development budget ledger. | User requested GSM8K/MMLU and asked to debug pass@4 first; the pre-registered cn_k12 test cannot be retroactively replaced. | `runs/v0-20261021-formal/external/SUMMARY.md`, `summary.csv`, `budget.json` |
| 24 | Selected evaluation budget: `max_new_tokens=4096`, 32 GSM8K test items pass@1, 32 MMLU items pass@1. At 2048 full R was severely truncated; at 4096 full R is 0.812 (GSM8K) and 0.438 (MMLU) with much lower truncation. | This is the "valuable test budget" requested: enough headroom for a 90% comparison, still small enough to run. | `runs/v0-20261021-formal/external/SUMMARY_n32_cap4096.md`, `runs/v1-gsm8k-search/SUMMARY.md` |
